# 2. Специфікація нефункціональних вимог (ISO/IEC 25010:2023)

| Категорія (ISO 25010) | Підхарактеристика | Конкретизована нефункціональна вимога | Кількісний індикатор / Метрика |
| :--- | :--- | :--- | :--- |
| **Performance Efficiency** | Time Behaviour | Швидкість повнотекстового пошуку та віддачі сторінки каталогу з фільтрами. | Затримка $p95 \le 120\text{ ms}$ при фоновому навантаженні 1 500 RPS. |
| **Performance Efficiency** | Capacity | Здатність приймати та обробляти запити на створення замовлень у пікові години розпродажу. | Пікова пропускна здатність $\ge 3 000\text{ RPS}$ без генерації помилок 5xx ($< 0.01\%$). |
| **Reliability** | Availability | Безперебійна доступність сервісу оформлення та оплати замовлень онлайн. | $SLA \ge 99.95\%$ (сумарний плановий/позаплановий простій $\le 4.38$ годин на рік). |
| **Reliability** | Recoverability | Автоматичне відновлення працездатності після аварійної зупинки інстансу БД. | $RTO \le 30\text{ c}$ (час перемикання на Standby-репліку), $RPO = 0$ (жодної втрати підтверджених транзакцій). |
| **Security** | Confidentiality | Захист персональних даних покупців та збережених адрес доставки згідно з GDPR. | Шифрування чутливих даних у БД за стандартом AES-256-GCM; обов'язкове шифрування трафіку TLS 1.3. |
| **Security** | Integrity | Захист від повторних списань та подвійного оформлення замовлення (Idempotency). | $100\%$ захист транзакцій за допомогою Idempotency-Key у заголовках API запитів на списання. |
| **Maintainability** | Testability | Можливість надійного автоматизованого тестування ядра платформи. | Покриття коду доменних сервісів (`Order`, `Payment`, `Inventory`) юніт-тестами $\ge 85\%$. |
| **Flexibility** | Scalability | Автоматичне горизонтальне масштабування робочих вузлів при стрибку навантаження. | Підняття додаткових реплік бекенду через HPA за $\le 60$ секунд при стабільному навантаженні CPU > 70% протягом 1 хв. |
