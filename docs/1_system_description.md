# 1. Опис системи та межі маркетплейсу (System Scope)

## 1.1. Загальний опис системи
**CloudMarket** — це хмарна масштабована E-Commerce платформа (High-Load маркетплейс), призначена для онлайн-торгівлі товарами різних категорій від незалежних мерчантів. Система забезпечує повний життєвий цикл електронної комерції: пошук та фільтрацію товарів у каталозі з кешуванням, керування персоналізованим кошиком, проведення захищених платежів, резервування залишків на складах та миттєве надсилання системних сповіщень.

## 1.2. Бізнес-цілі (Business Goals)
1. **Висока відмовостійкість у період акцій:** забезпечення стабільної доступності ($SLA \ge 99.95\%$) під час планових розпродажів (Black Friday, Cyber Monday) та сплесків трафіку.
2. **Мінімальний Time-to-Market для MVP:** запуск базового функціоналу ядра за 3 місяці з подальшим поступовим масштабуванням.
3. **Висока конверсія кошика:** скорочення часу обробки та підтвердження замовлення до $< 1$ секунди.

## 1.3. Межі системи (System Scope)
- **Входить у межі (In Scope):**
  - Web SPA та мобільний додаток для покупців (каталог, кошик, особистий кабінет).
  - Портал мерчанта (керування картками товарів, цінниками, складськими залишками).
  - Модуль обробки замовлень (Order Lifecycle Service).
  - Сервіс складського обліку (Inventory & Stock Reservation).
  - Сервіс розсилки мультиканальних сповіщень (Email/Push/SMS).
- **Поза межами (Out of Scope):**
  - Прямий банківський еквайринг (делегується через зовнішні платіжні шлюзи Stripe/LiqPay).
  - Фізична кур'єрська служба (інтеграція з логістичними операторами Nova Poshta / DHL через Webhook API).

## 1.4. Матриця стейкхолдерів (ISO/IEC/IEEE 42010:2022)

| Роль стейкхолдера | Представник | Ключові занепокоєння (Concerns) | Вплив на архітектуру |
| :--- | :--- | :--- | :--- |
| **End User (Покупець)** | Клієнт платформи | Миттєвий пошук у каталозі ($< 150\text{ ms}$), захист карткових даних, збереження кошика між різними сесіями та девайсами. | Висуває вимоги до низького Latency, розподіленого кешування (Redis/CDN), Stateless JWT сесій та Usability. |
| **Merchant (Продавець)** | Представник магазину-партнера | Своєчасна синхронізація залишків на складі, точність взаєморозрахунків, зручний імпорт карток товарів (CSV/JSON/API). | Формує вимоги до суворої транзакційної цілісності (ACID), захисту від оверселінгу (Race Conditions) та Batch Processing. |
| **Business Owner (CEO / Стейкхолдери)** | Інвестор проєкту | Вартість володіння хмарою (TCO), швидкість виходу на ринок (Time-to-Market), окупність інфраструктури, масштабованість. | Визначає вибір архітектурного стилю Modular Monolith на старті з Cloud Native підходом для економії бюджету. |
| **DevOps / SRE-інженер** | Команда експлуатації | Простота автоматизації CI/CD, спостережуваність (Distributed Tracing, метрики, логи), автовідновлення та автоскейлінг подів. | Висуває вимоги до контейнеризації (Docker), оркестрації (K8s/HPA), моніторингу (Prometheus/Grafana) та Health Checks. |
| **Security Officer** | Фахівець з кібербезпеки | Безпека платежів, відповідність PCI-DSS, регламенту GDPR, запобігання DDoS та брутфорс-атакам, аудит дій. | Визначає вимоги до ізоляції платіжних даних, шифрування (TLS 1.3, AES-256), WAF та незмінних аудиторських логів. |
